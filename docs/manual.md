# Live Enhance Lights 使い方ガイド

観客のスマホをブラウザだけで**ペンライト（発光面）**にして、マスター（あなた）が
コンソールから**手動でシーンを切り替える**ライブ演出アプリの操作説明です。
（現時点の仕様に基づく内容です）

---

## 0. 基本情報

| 項目 | 内容 |
|---|---|
| 観客用URL | `https://＜あなたのVercel URL＞/` |
| マスター用URL | `https://＜あなたのVercel URL＞/master` |
| マスターのパスコード | `5150`（既定値。Vercelの環境変数で変更可） |
| 同期方式 | Ably（本番）。マスターが押した瞬間に全端末へ配信 |
| 音源同期 | なし（曲に合わせて手動でコマ送り） |

- **アプリのインストールは不要**。観客はURL/QRを開くだけ。
- 通信は各端末のモバイル回線 or 会場Wi-Fi。マスターと観客は同じネットワークでなくてOK
  （Ablyのクラウド経由で同期するため）。

---

## 1. 観客側の流れ

1. 観客用URL（またはマスター画面に出るQR）をスマホのブラウザで開く
2. **フォロー画面**が表示される
   - 「Instagram でフォローする」→ バンドのアカウントが開く（@theroxgwo）
   - 戻って「フォローした → 次へ」
   - 光の点滅に関する**注意書き**を確認して「同意して入場する」
3. 画面が全画面の発光面になる。以降はマスターの操作でリアルタイムに色・演出が変化
4. 画面を**タップすると全画面表示のオン/オフ**が切り替わる

観客へのアナウンス推奨：
- **画面の明るさを最大**に
- **自動ロック（スリープ）をオフ**に（アプリ側でも抑止しますが、端末により効かない場合あり）
- 一度入場した端末は、次からフォロー画面を飛ばして直接ライトになります

> フォロー確認は「自己申告」です（Instagramの仕様上、第三者アプリはフォロー有無を判定
> できないため）。ゲートではなく導線として機能します。

---

## 2. マスターコンソールの全体像

`/master` を開き、パスコード `5150` で入室。画面上部に：

- **公演タイトル**（最高は今 TWO-MAN LIVE）
- **本番 / 編集** モード切替
- **📱 接続台数**（今つながっている観客スマホの数。Ablyオフのデモ時は `N(demo)` 表記）

その下に**曲タブ**、さらに下に**4×3＝12個のシーンボタン**が並びます。

---

## 3. 編集モード（事前の仕込み）

上部の「**編集**」を押すと、シーンを作り込めます。

### 曲（セットリスト）の管理
- 曲タブの「**＋曲**」で曲を追加
- タブを**ダブルタップ/ダブルクリックで曲名を変更**
- 選択中タブの「**×**」で曲を削除

### シーンボタンの割り当て
- **空きボタン**をタップ → 新規シーンが作られ、右（下）の**編集フォーム**が開く
- **既存ボタン**をタップ → その場で編集
- 編集フォームの項目：
  - **ボタン名**（本番で表示される名前。視認性のため簡潔に）
  - **パターン**（下表）
  - **色 / 色1・色2**（グラデ時は2色）
  - **BPM**（明滅・ストロボ時）／ **繰り返し**（オフ＝1回だけ鳴らして点灯保持）
  - **表示文字 / フォント / サイズ**（テキスト時。**改行可**）
  - **画像アップロード or 画像URL / 表示方法**（画像時）
  - リアルタイム**プレビュー**（実機に近い**スマホ縦長**表示）
  - 「**このボタンを空にする**」で割り当て解除

### パターン一覧

| パターン | 動き | 主な設定 |
|---|---|---|
| 単色 | 指定色でベタ点灯 | 色 |
| 明滅(BPM) | BPMに合わせて**色1↔色2**を滑らかに切替（色2を黒にすると増減光） | 色1・色2・BPM・繰り返し |
| ストロボ(BPM) | BPMで**色1↔色2**を点滅（**安全上3Hz上限**にクランプ） | 色1・色2・BPM・繰り返し |
| グラデーション | 2色がゆっくり移り変わる | 色1・色2 |
| レインボー | 虹色に色相が回転 | （色指定なし） |
| テキスト | 黒背景に大きな文字（**改行可**） | 表示文字・フォント・サイズ・色 |
| 画像 | 画像を全画面表示 | 画像・表示方法(全体/いっぱい)・**背景色** |
| 暗転 | 真っ黒（消灯） | （なし） |

- **テキスト**：改行して複数行にできます。フォントは**システムフォント**（ゴシック/明朝/
  丸ゴシック/等幅）から選択、サイズは**小/中/大/特大**のプリセット。文字色も指定可。
- **明滅/ストロボ**：**色1↔色2**の2色切替です。色2を黒にすれば従来どおりの増減光/点滅、
  黒以外にすれば2色が入れ替わる演出になります。
- **画像**：R2を設定していれば「**画像をアップロード**」ボタンから追加（自動で縮小して軽量化）。
  もしくは**画像URL**を直接貼り付け。表示方法は「全体表示（余白あり）」「画面いっぱい
  （トリミング）」から選べ、**背景色**（全体表示のときの余白の色）も指定できます。画像の準備は次節を参照。

> **安全配慮**：ストロボや高速明滅は点滅頻度を最大3Hzに自動制限しています。過度な高速点滅は
> できない設計です。

### 画像を使う準備（Cloudflare R2）
画像は「**Ablyには参照だけ送る／実体はR2からCDN配信＋端末キャッシュ**」の構成で、
利用料をほぼ増やさずに表示できます。使うには一度だけ R2 を設定します。

1. Cloudflare で **R2 バケット**を作成
2. バケットを**公開**にして公開URL（`https://pub-xxxx.r2.dev` 等 or カスタムドメイン）を控える
3. **R2 API トークン**（アクセスキー/シークレット）を発行
4. バケットの **CORS** で、アプリのドメインからの **PUT** を許可（ブラウザ直アップロードのため）
5. Vercel の環境変数に設定 → **Redeploy**：
   - `NEXT_PUBLIC_UPLOAD_ENABLED=1`（アップロードボタン表示）
   - `R2_ACCOUNT_ID` / `R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY` / `R2_BUCKET`
   - `R2_PUBLIC_BASE_URL`（公開URLのベース／末尾スラッシュなし）

> 未設定でも「画像URL貼り付け」だけは使えます（どこかに置いた画像URLを入力）。
> アップロードボタンは R2 設定後に表示されます。

### プログラムの保存・持ち出し
- 編集内容は**そのブラウザに自動保存**（localStorage）されます
- 右側の「**書き出し(JSON)**」でファイル保存、「**読み込み**」で復元
- 「**サンプルに戻す**」で初期構成に戻せます

> ⚠️ **セットリストはマスターとして使う端末・ブラウザに保存**されます。当日使う端末で
> 組むか、事前に「書き出し(JSON)」→当日の端末で「読み込み」してください。

## 4. 本番モード（当日の操作）

上部の「**本番**」を押すと操作画面になります。

- **12個のシーンボタン**：押すと**全観客端末が即そのシーンに切替**。押したボタンは白く強調
- **曲タブ**で曲を切り替え（曲ごとに12個のボタン）
- **■ 暗転（全消灯）**：ワンタップで全端末を黒に
- **現在の出力プレビュー**：今流している演出と名前を確認
- **📱 接続台数**：観客の接続数
- **参加用QR / URL**：観客に見せて読み込んでもらう

操作はシンプルに「**曲を選ぶ → 曲中はボタンを押して演出を送る → 転換は暗転**」の繰り返しです。

### MIDIコントローラーで操作する（任意）
本番モード右側の「**MIDI操作**」で外部MIDIコントローラーから操作できます。
（**Chrome / Edge のみ**。SafariはWeb MIDI非対応。HTTPS＝Vercelで動作）

- **接続する**：ボタンを押してMIDIアクセスを許可 → つながった機器名が表示されます
- **Program Change（PC）＝ 曲の切替**：PC番号（0始まり）が曲の並び順に対応
  （PC 0 → 1曲目、PC 1 → 2曲目…）
- **Control Change（CC）＝ シーン発火**：`開始CC番号`から12個ぶんが、ボタン1〜12に対応
  （例：開始CC=16 なら CC16→ボタン1、CC17→ボタン2…）。値が64以上で発火
- **受信**欄に、今受け取ったPC/CC番号が表示されるので、それを見ながら`開始CC番号`や
  コントローラー側の割当を合わせてください（設定は端末に保存されます）

> スマホのタップ操作と併用できます。MIDIはあくまで追加の操作手段です。

## 5. 当日の運用フロー（推奨）

1. **事前**：編集モードでセットリストを作成 →「書き出し(JSON)」でバックアップ
2. **会場入り**：当日マスターに使う端末で `/master` を開き入室（必要なら JSON 読み込み）
3. **開演前**：観客に参加用QR/URLを案内（SNS・張り紙・MC・スクリーン等）
   - 「フォローして光らせよう！」の一言があると導線として効果的
4. **リハ**：数台のスマホで実際に色・明滅・暗転を確認。接続台数が増えることも確認
5. **本番**：曲に合わせてボタンを送る／転換で暗転
6. 予備として**マスター端末は電源・通信を安定**させておく（モバイル回線併用が安心）

## 6. うまく動かないときは

| 症状 | 確認ポイント |
|---|---|
| 観客の画面が変わらない | マスターの📱接続台数が増えているか。増えないなら観客がAblyに繋がっていない |
| 接続はするが同期しない | マスターと観客の`?show=`（またはURL）が同じ公演か。ブラウザConsoleの`[LEL]`ログで`channel = show:...`が一致しているか確認 |
| 画面がスリープする | 端末の自動ロックをオフ。HTTPS（Vercel）で開いているか（Wake Lockは要HTTPS） |
| マスターに赤いエラー | Consoleの`[LEL]`ログ／エラーメッセージを確認 |
| 画像アップロードが失敗 | R2の環境変数が揃っているか。R2バケットの**CORSでPUT許可**があるか。`NEXT_PUBLIC_UPLOAD_ENABLED=1`か |
| 画像が観客に出ない | 画像URLが**公開**でアクセスできるか（ブラウザで直接開けるか） |

### 診断ログ `[LEL]` の見方
ブラウザの開発者ツール → Console に、動作ログが `[LEL]` 付きで出ます。
- マスター：`master publish: ＜シーン名＞`（ボタンを押した時）
- 観客：`audience received: ＜シーン名＞`（受信した時）
- 両者の `connection: connected` と `channel = show:the-rox-quattro-live` の一致

> 実機テストが落ち着いたら、このログは削除してスッキリさせられます（依頼ください）。

## 7. 現時点の仕様・制限

- **グループ分けなし**：全端末が常に同じ演出（席ブロック別の出し分けは未対応）
- **フォロー判定は自己申告**（Instagram API仕様のため自動判定は不可）
- **観客リセット機能なし**（Android×Chromeで不安定だったため削除済み）
- **セットリストはマスター端末のブラウザ保存**（サーバ保存ではない）

## 8. 運用・コストのメモ

- ホスティング：Vercel（Next.jsアプリ）／同期：Ably／画像：Cloudflare R2
- Vercelに設定する環境変数：
  - 必須2つ：`ABLY_API_KEY` と `NEXT_PUBLIC_ABLY_ENABLED=1`
  - 画像を使う場合：`NEXT_PUBLIC_UPLOAD_ENABLED=1` と `R2_ACCOUNT_ID` /
    `R2_ACCESS_KEY_ID` / `R2_SECRET_ACCESS_KEY` / `R2_BUCKET` / `R2_PUBLIC_BASE_URL`
  - ショー情報（タイトル・IG・showId・パスコード）はコード既定値に設定済み
- 目安コスト：手動コマ送りのためメッセージ従量はほぼゼロ。画像もAblyには参照のみ・実体は
  R2からCDN配信＋端末キャッシュのため転送量は小さい。実費は同期基盤の固定費が中心で
  **公演月あたり数千円**程度（詳細は `README.md`）
- **セキュリティ**：`ABLY_API_KEY` はリポジトリにコミットせず、Vercelの環境変数のみに置く。
  キーが外部に露出した場合はAblyダッシュボードで再生成（rotate）する。
- パスコードやショー情報を変えたら、Vercelで**再デプロイ**（`NEXT_PUBLIC_`系はビルド時反映）
